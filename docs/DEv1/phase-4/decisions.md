### P4-D10 source-discovery option comparison

| Dimension | Option A — Silver canonical accepted-change API (preferred candidate) | Option B — bounded full canonical rescan |
|---|---|---|
| Correctness | Silver emits exact contiguous dispositions only through its applied change prefix, truncates on an unapplied conflict, binds captured Hc/Hi/Sc/Si and safe invalidation prefix in a page receipt; invalidations remain independently consumed. | Correct only if every relevant run/time scope is rescanned; Gold dedupes semantic identity/revision/content. Never resume by event ID. |
| Multiple runs | Namespace-global feed discovers every journaled run and binds each entry to run, generation, digest and manifest identity; event-free runs are not discoverable from event journal alone. | Gold needs trustworthy inventory for empty runs; direct physical dimension-table discovery is not approved. An explicit run list proves only that configured scope. |
| Late/out-of-order | Sequence continuation discovers late events independent of event ID/time; windows still use simulation time. | Re-scan all impacted scopes or entire retained run; changed events sorting before a previous event key must be found. |
| Progress/recovery | Receipt binds sequence boundary; separate invalidation cursor; crash resumes only if API provides durable boundary-safe continuation, otherwise discard stage and restart at frozen boundary. | Crash/churn discards stage and rescans full scope; replay costs a new full scan; changed source creates a new replay manifest/ID. |
| Cost/API/gate | Work proportional to changes plus discovery; requires Silver-owned API, contract approval and actual race/restart tests. | O(N) reads each scan plus O(N) temporary SQLite stage I/O; requires measured CPU, RSS, wall-time, disk and quotas. Current API has no public receipt or bounded streaming sink. |

## Risks of retaining legacy assumptions

Direct V2 readers evade V1 validity; hash-key ordering is not simulation-time ordering; zero lateness can finalize too early; revision cap 1 can refuse legitimate corrections; V2 quality/context can turn absent values into zeros; four-direction/cadence expectations can misstate coverage; V2 replay manifests bind wrong database/tables; V2 serving views encode unapproved formulas. Each risk has acceptance coverage in `acceptance.md`. D3-10 resolves runtime topology; it does not itself approve these mechanical policies.
