# UP-01 — Deterministic schedule, lifecycle và verified horizon

**Phương án do owner chọn.** Producer ranges + sparse outcomes + durable settled horizon. Entry cần amendment D-A14 có hiệu lực và authorization riêng từ source, Raw/Bronze/Silver và Gold owners. E-01 ghi clock 60.04/300.05, sai lệch 0.04s, nên không dựng lịch quá khứ từ cadence danh nghĩa.

## Contract v1 của metadata mới

- Archive bất biến `observation_schedule_v1`: schedule ID = SHA-256 canonical JSON của schema version, run ID/generation, manifest/config/topology digests, sorted participant/direction IDs, first tick, period ticks, tick unit microseconds, simulation step và cycle base. Ordinal k ≥ 0; due tick = first + k×period. Entry chỉ nhận configured fixed step/cadence biểu diễn chính xác bằng integer ticks và lattice khớp step. Do not round actual simulation timestamp. Capture tại due step; late clock hoặc mismatch là explicit unsuccessful outcome, không retime. Core vẫn dùng actual canonical timestamp và half-open 60/300s.
- Slot key (run context, schedule ID, intersection ID, ordinal); direction là thuộc tính population của intersection. Cycle sequence dành trước theo base + ordinal, kể cả failed slots. V1 event ID vẫn là hàm version/run/intersection/cycle, actual time và completed step hiện hữu vẫn ghi nguyên. Một reset phải dùng run ID mới nếu V1 event key sẽ trùng, cùng generation/manifest mới, không tái dùng identity.
- Durable journal version 1: append-only sequence, previous record digest, schedule ID, lifecycle state, settled ordinal inclusive, terminal cutoff in ticks nếu terminal, default-success contiguous range, sparse exception (ordinal, capture failure/missed + reason) và references tới immutable revision nếu correction. All-participant cycle là đơn vị success; producer linkage qua existing event IDs suy ra từ schedule/cycle và Outbox rows, không cần copy full payload vào metadata. Exception phải được durable record, absence chỉ mang nghĩa success trong sealed contiguous range. O(ranges + exceptions + lifecycle changes) cho archive metadata; source vẫn giữ normal Outbox events.
- Lifecycle REGISTERED → RUNNING ↔ PAUSED → ENDED/ABORTED. Pause không advance simulation clock, settle một phần hoặc tạo slot. Terminal cutoff từ authoritative last processed tick. Restart kiểm tra actual checkpoint/cycle/slot continuity; nếu không chứng minh được thì abort at last proven cutoff hoặc giữ UNKNOWN, tạo run mới. Không gán success/missing cho phần không chứng minh được. Partial first/last không publish như full window.

## Ba boundary và processing sequence

1. **Producer settled horizon P.** Backend compute due tick, capture toàn bộ participant. Trong same Outbox SQLite transaction, append all frozen observation rows hoặc ghi durable explicit exception; chỉ advance range cursor cho prefix đã settle. Capture xong nhưng chưa commit thì restart inspect durable cursor, retry cùng slot chỉ khi cùng simulation state và immutable payload evidence; nếu mất continuity, dừng suffix ở WAITING/UNKNOWN. Commit rồi crash trước send thì Outbox retry same bytes. Crash khi export thì re-export same hash/version, không tạo record mới với nội dung khác. Flush horizon export bounded theo range/lifecycle, kể cả khi không có event mới. Atomic export từ committed journal qua run archive immutable content-addressed segments; publish head only after segments durable. Pause/end/reset tạo metadata-only record. Không dùng mutable JSON manifest như sole durable ledger.
2. **Silver verified boundary S.** Đọc schedule/segments qua verified run archive resolution, không suy đoán delivery từ P. Với mỗi default-success slot, đi từ derived V1 event ID tới matching Raw/Bronze identity và contiguous Silver change proof hiện có. Kiểm tra run/cycle/time/topology/participant, fact validity/hash và linked invalidation. Advance only across fully resolved expected participants, hoặc explicit producer exception. Delayed/missing identity, unlinked quarantine và unexplained retention gap chặn prefix. Explicit verified conflict giữ disposition INVALIDATED/CONFLICT với linked sequence, không xóa khỏi expected population. Persist verified horizon pages (P digest/revision, verified ordinal range, highest required CHANGE/INVALIDATION seq, outcome/schedule digest). Expose additive public schedule discovery + paginated receipts theo run/metadata cursor, với captured finite independent boundary và event/feed receipt linkage. Metadata receipt version 1 riêng, existing public feed v1 bytes/ACK semantics giữ nguyên. Sparse output may use cumulative watermark proofs; reuse verified linkage incrementally, không rescan prefix theo mỗi KPI.
3. **Gold applied boundary G.** Separate monotonic metadata cursor scoped to Silver binding. Verify metadata receipt, schedule digest, prefixes, required feed cursors và affected range. Apply khi both committed Gold CHANGE và INVALIDATION cursors ≥ S watermarks, trong một Gold-local transaction với metadata cursor, eligibility/recompute obligations và fence bumps. Trước đó pending/WAITING, kể cả producer đã settle. Invalidation-before-change giữ nguyên. Metadata-only receipt kích hoạt promotion/recheck qua durable indexed intent, không chờ next observation. Entire missing window suy ra từ full closed timeline + applied exceptions/absence proof, ghi status ở timeline và không tạo event hay fake zero fact. Nếu interval có members và không có observation ở phía sau end, future integration cần owner-approved terminal eligibility hook để dùng G-backed cutoff và enqueue existing proof path. Không bypass Core materialization, invented cursor advance hay direct Core COMPLETE. Scope hook là UP-01 Gold compatibility design/A-I02 integration; khi hook chưa supported, official terminal publication bị chặn.
4. Corrections chỉ append revision có lineage. Conflict/withdrawal của schedule/outcome trước hết phát public metadata invalidation gắn affected ordinal range; Silver/Gold suppress/recheck và bump epoch/generation trước apply replacement. Verified receipt yêu cầu processed metadata invalidation prefix cùng change/invalidation watermarks. Schedule topology/cadence semantic change tạo new scope, không sửa denominator cũ in place. Old corrected record remains auditable, old cached token stale. Replay pins metadata boundary/digests along with Core boundary.
