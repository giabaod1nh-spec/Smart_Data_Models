## Independent correctness oracle and evidence protocol

For tests only, derive source expectations independently from Bronze SQLite `v1_sequence`, `v1_changes`, `v1_identity`, `v1_invalidations`; Silver per-sequence obligations/invalidation provenance; ClickHouse materialized rows/reconciliation; immutable archive manifests/topology. Derive Gold expected membership, suppression and impacted windows independently from source event time and the selected 60s/300s half-open specification. The oracle must detect skipped/duplicate sequences, wrong dispositions, false bundles, wrong transition hash, wrong window boundary, stale work completion and lost invalidation.

Retain repository revision, exact test command/environment, source binding, request/response/receipt bytes, independent oracle output, Gold DB snapshots before/after crashes, cursor CAS results, work/membership/dirty records, service inventory, query logs, CPU/RSS/WAL/disk/resource samples and retained failures. Label fixtures, mocks, actual Silver, actual Gold Stage B and end-to-end benchmark distinctly. Do not replace failed inherited tests with blanket skips.

## Performance evidence and verdicts

Pre retained evidence: 150 entries applied and acknowledged over 600s (0.25/s), 255 sequences/bundles, 221 receipts, 5,255,148 encoded bytes, controlled backlog 30 after two-minute consumer pause, drained in 28.23s; page plus test acknowledgment p50/p95/p99 828.1/949.0/1,152.3ms. It measures Silver feed and test-only durable consumer, not actual Gold or the full live path; the pause was not a true producer burst and 0.25/s is not maximum sustainable throughput. The initial five-second cycle profile could not sustain offered rate because apply/replay took around 14–15s per five-observation cycle. Source evidence is in `pre/evidence/capacity.json` and `acceptance-result.md`.

Core then performs the representative end-to-end A–H suite. A five-intersection, one-cycle-per-wall-second profile would offer five observations/s if verified from producer behavior; this is a workload assumption, not a universal cadence. Do not introduce a fixed 10-second SLO. Profile actual bottlenecks; if insufficient, create separately approved remediation with before/after measurement and preserve accepted upstream contracts. No source rewrite, event drop, reconciliation bypass or producer pause to manufacture a pass.

Every report gives independent outcomes: **CORRECTNESS: PASS/FAIL**; **CAPACITY: SUSTAINABLE AT TESTED WORKLOAD / BURST RECOVERY VERIFIED / CAPACITY INSUFFICIENT / INCONCLUSIVE / NOT MEASURED**; **OPERATIONAL READINESS: PASS/FAIL**. Correctness PASS is not capacity or deployment readiness. Core makes no business KPI or Gold-to-Dashboard latency claim.

## Exit gate

Stage B exit requires all applicable C/R/I assertions against actual Gold + Silver; durable receipt and independent cursor correctness; invalidation-before-change acknowledgment; window membership/state-dimension rules; recovery/replay isolation; no business-mart writes; V1/V2 isolation; resource bounds; retained historical architecture failures; and explicit independent correctness/capacity/readiness verdicts. Capacity objectives and production activation remain owner/deployment gates and cannot be inferred from a foundation correctness PASS.
