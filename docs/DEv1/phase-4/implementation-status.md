## Final review decisions

1. **Public errors.** `de/silver/incremental_reader.py:_translate_feed_error` maps internal `CURSOR_GAP` to `RETENTION_GAP` and `SOURCE_SCHEMA_UNSUPPORTED` to `SOURCE_BINDING_CHANGED`. Apply the public exception's retryability directly. Session construction has a separate `CanonicalReadError` surface and needs its own health origin. EMPTY never changes progress. Surface nonretryable oversized records and entry deadlines with actionable cause. Test both translation and Gold receipt/state faults. Gold-local faults never get a Silver code.
2. **Receipt retention.** Verify complete canonical bytes in memory before accepting each page, using the public serializer and the distinct digest projection. Keep immutable headers, exact coverage, per-stream immutable hashes, acknowledged dispositions, bundle hashes, run and event provenance, suppression and linked work receipts in SQLite. Preserve receipt and transition metadata for the lifetime of the binding. Retain full canonical bytes only as scoped acceptance artifacts for selected deterministic fixtures, with disposable fixture data and no live export. A historical digest alone cannot reproduce the old payload or independently revalidate historical content. Full historical bytes in Gold would duplicate Silver data without improving current-effective recompute. Measure DB/WAL growth and verify exact redelivery does not create new obligations.
3. **Recoverable window inputs.** Select indexed Gold membership and exact requalification via the existing public change API. For member source sequence `s`, request `after_change_sequence=s-1,max_entries=1`. The public reader point-reads the consecutive requested range (`de/silver/incremental_reader.py:_build_feed_page`). This is a single-entry range, with one verification per indexed member, even for sparse/interleaved runs. Recheck receipt, immutable transition, run/revision and bundle hash. Exclude suppressed members. A member which has since transitioned to conflict must wait for durable invalidation and a fresh work generation. Stream at most one bundle at a time, using bounded resumable work quanta. Start/end discovery and each member receipt must share the same Bronze invalidation high-water for a successful proof. If it moves, restart that work proof, allowing unrelated change appends and leaving live cursors intact. The completion transaction also compares the local generation and owner. These checks establish the input set at the observed local generation with per-entry canonical evidence and a finite invalidation fence. A conflict arriving afterward converges through the feed. Durable completed work contains only input identity/provenance; partial digest checkpoints are dispensable and restart from the current generation. This costs O(window members) public reads, which needs measurement and can be delayed by continuous invalidation churn. Persisting all bundles (A) would multiply retention costs and still need validity checks. The legacy run/digest/time scan (C) requires whole-scope revalidation, can restart on unrelated appends, and has no production receipt. A Silver point/batch extension (D) could reduce amplification if measured costs justify an independently approved contract; the current single-entry range is sufficient for correctness.
4. **Independent scheduling.** Use discovery's fixed ready invalidation prefix even if changes return lag or a blocked prefix. Process independent feed slices, a bounded change slice and a bounded work slice fairly. Hold at most one change page while catching its fixed Pi. If the durable invalidation cursor already covers Pi, send no backward request. Observe source lag separately and back off blocked lanes. Verify pending-mirror behavior, fixed-Pi ordering and progress while blocked.
5. **Time and eligibility.** `contracts/events/intersection-observation-v1.schema.json` declares finite nonnegative simulation time via schema and `contracts/traffic_observation.py:validate_observation`. Silver mirrors the number in `simulation_time_seconds` (`de/silver/fact_builders.py`). Keep fractions as supplied for provenance. Compute integer endpoints using `int(time) // duration * duration` after validating finite nonnegative numbers and SQLite endpoint range. Integer division avoids float quotient rounding near boundaries. Retain full 60s/300s duration at run end. For each pinned run, a durably consumed valid event time at or beyond a discovered window's end makes it a candidate. No empty intervals are synthesized. Open windows retain membership and work intent continuously. Already eligible windows stay eligible and late changes enqueue a new generation. This is scheduling evidence only. Completeness remains UNKNOWN, finality DISABLED and lifecycle independent. Test both sides of fractional boundaries, out-of-order input and terminal windows.
6. **Replay and lifecycle.** Request Silver source namespace `live` in every mode. Gold replay owns a deterministic processing namespace and separate DB/lock, with manifest binding both captured allocator and applied boundaries, full run identity, scope and contract/schema/processor versions. Global sequences are accounted as replay advances but work is scoped separately. Require stable boundaries at startup, every bounded read/work and finish. Abort that replay identity on changed authority; retry transient outages. The public feed has verified immutable archive identity but no public current lifecycle status or separate registry freshness result. Persist lifecycle UNKNOWN; report source/query faults separately. Event-free runs remain outside discovery.
