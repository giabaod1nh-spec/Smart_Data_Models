# Performance Acceptance plan

**Not executed.** This plan certifies a complete SUMO→completed Gold foundation path only after optimization and owner-approved G1 objectives. It does not certify Phase 4B KPI/mart/serving performance.

## Gates and tiered benchmark levels

G0 freezes the workload/compatibility envelope and authorizes hardening, instrumentation and profiling. G1 occurs after instrumented evidence and freezes numerical throughput, latency, queue, recovery, resource, history and realtime targets with rationale. No pass/fail numeric threshold is approved before G1.

| Level | Purpose / recommended duration | Entry / workload | Measurement and independent evidence | Exit and early stop |
|---|---|---|---|---|
| L0 | Operation/batch microbenchmark; duration sufficient to collect repeats and tail samples | G0; one isolated operation or bounded batch, explicit data/CH version and source distribution | Nested spans, query attribution, exact disposition and output oracle, RSS/SQLite/WAL/CH | Root cause attributed or explicitly unmeasured; abort on semantic mismatch, unsafe source or instrumentation distortion |
| L1 | 2–5 min smoke, severe regression detection | L0 correctness; W1 or W2 stated, isolated state, declared warm-up | Offered source vs completed capture, per-stage queues/costs, Gold ACK/work sample, independent prefix/membership | Smoke only; not sustained certification. Stop on integrity fault, source pacing mismatch, unsafe disk/RSS, unrecoverable dependency |
| L2 | 10–15 min matched iteration | L1 pass; same before/after workload, versions, resource envelope, seeds/history | Early/mid/late stage rates and slopes, member reads/work, query/resource and oracle, repeated equivalent runs as needed | Candidate has attributable improvement without queue transfer; otherwise reject/inconclusive. Stop on sustained growth likely to breach safe budget |
| L3 | 30–60 min integrated qualification, several 300s windows where pacing allows | L2 stable; W2 full relevant application stack; G1 owner-approved objectives | Global stage queues, eligible 60/300 work age/completion, SUMO/realtime, CH/Kafka/containers, full oracle; burst/recovery where bounded | Qualifies for L4 only if stable and no unresolved correctness/resource issue. Stop on persistent positive trend, fidelity or realtime breach |
| L4 | 2–4 h or longer only when justified by history/resource drift and final confidence | L3 pass; G1 owner-approved; explicit history cohort and outage budget | endurance, history/index/merge, WAL/disk, rate/age trends, multiple completed windows, global recovery and full drain | Final sustained evidence. Any stopped failure remains FAIL/INCONCLUSIVE; preserve all raw evidence. Not default for each tuning iteration. |

Durations are recommendations, not SLOs. Select final level duration from intended workload, number of completed 60/300 proofs, backlog confidence/repeated-run variance, resource growth, retained history and actual host capacity. Warm-up is predefined and retained separately. Sample at a cadence yielding at least 30 observations/analysis segment where practical; account for autocorrelation and overhead. Do not run L4 until shorter levels pass.

Each trial records commit and image/config hashes, W1/W2/W3 identity, step/capture/publish config, simulation/wall pace, expected cycles, completed captures, entities/cycle, payload bytes, topology/seed/scenario, app services, initial history/backlogs, host/storage/Docker limits, CH/Kafka versions, external contention, start/stop and warm-up rules. Separate actual accelerated SUMO from deterministic replay/component fixtures. Component rate is never full-path capacity.

### PA-11 Gold profiles

- **G-A — Gold local ceiling:** controlled fixture isolates receipt verification, SQLite transactions, membership insert, suppression, work scheduling and generation handling. Report strictly as fixture-local component capacity.
- **G-B — Actual canonical read capacity:** real Silver/Bronze retained evidence, actual ClickHouse and public Silver read API. Measure per-entry evidence, ACK, actual member materialization, 60/300 completions, query amplification and conflict/invalidation. A pre-materialized source may isolate read path only if source verification cost remains real.
- **G-C — Full E2E:** `SUMO→Outbox→Kafka→Raw→Bronze→Silver→Gold completed work`; verify all queues, throughput, latency, recovery, shared resources, current work generations and independent full drain.

A fast mock feed is not G-B or G-C. Gold cursor catch-up is not completion. At W2 estimated five observations/s, workload may require ~10 member retrievals/s before recomputation; actual counts and distributions come from the approved run.

## Independent oracle and full drain

Expected source identity/payload comes from run manifests, Outbox and Kafka evidence, not optimized downstream output. Raw comparison checks exact bytes and physical delivery identity. Bronze oracle recomputes duplicate/conflict disposition, journal/invalidation identity and lineage. Silver oracle computes expected facts, availability, value and lineage from accepted event/archive; compare validity transitions, obligation hashes and applied prefixes. Do not infer full historical validity from current Silver validity row alone. Gold receipt headers prove interval/hash identity where retained, not arbitrary old payload reconstruction. Independently calculate half-open epoch-zero 60/300 memberships, current suppression, input transition/bundle identity, current generation, and completed eligible work. At final frozen boundary account all stages; terminal OPEN windows are distinct from eligible incomplete work.

## Global recovery and backlog criteria

For each queue report input/output in its own unit, backlog slope and uncertainty, age distribution, bytes, peak, retries and resource. Analyze early/middle/late and bounded cyclic peaks vs sustained growth; final zero snapshot alone fails. Recovery starts at burst end or dependency restore; ends only when Outbox/Kafka/Raw/Bronze/Silver (both lanes and reconciliation) / Gold ACK lanes and current-generation eligible/dirty work return to G1 envelope with W2 arrivals continuing. Record maximum downstream backlog after upstream catch-up and total global recovery time. Use `μ ≥ λ+B/T` only as an estimate to set test demand; PA-04/05 global drain is proof.

## Persistent-state compatibility and rollback

For each persistent representation change, test old code/old state, new code/old state, new code/new state, and old code/new state (supported or explicitly forbidden). Define backup/restore boundary, forward recovery, retained source requirement, migration recovery, reconciliation and operator steps. An image rollback does not imply DB rollback. Never truncate, delete or rewind authority. On failure stop worker safely, preserve state/source, restore compatible code/config, revalidate binding/cursors, reconcile independently and resume only after oracle passes.

## Verdict rules and Phase 4B gate

PASS only when all required correctness, stable backlog, completed Gold work, recovery, resource, history, realtime and evidence criteria meet G1. FAIL for semantic mismatch, skipped offset/cursor, unfinished eligible work, positive persistent queue growth, unbounded resource, source pacing/fidelity regression, unacceptable realtime regression or oracle failure. INCONCLUSIVE for missing attribution, insufficient completed windows, insufficient run duration/confidence or incomplete samples; do not convert to pass.

Phase 4B remains blocked until Core correctness hardening and Phase 1–4A regressions pass, representative workload and eligible Gold work are sustainable, global recovery and conflict/replay/history scenarios pass, resource/realtime/retention envelope is approved, no critical blocker remains, and owner accepts evidence. Later KPI/mart/Spring API/Dashboard requires separate acceptance.
