# Performance Acceptance plan

This is a future campaign design, not an executed acceptance. Use the historical-comparable and intended-operation workload profiles from `requirements.md`; test only isolated disposable stacks for faults. No current SLO or production capacity is certified.

## Controlled benchmark framework

Extend/reuse `de/tools/gold_core_capacity.py` for isolated Compose preparation, producer/sampler and independent prefix oracle. It already supports a generated isolated pipeline profile and JSON sampling, but needs: immutable workload manifest/config hash; warm-up/steady/drain/recovery phases; run identity/seed/topology capture; CPU/RSS/disk/network/container samples; stage backlog ages/bytes; explicit late/conflict/invalidation workloads; query attribution; history sizing; long-run and full-drain independent oracle; repeated trials; and optional normal app stack. Keep raw series, not only summaries.

Each trial declares: commit, image digests, SUMO version/config and step, capture cadence, scenario/seed, topology/participants, payload size distribution, expected observation count/rate/bytes, normal or accelerated pacing, test profile, service configs/resources, ClickHouse/Kafka versions, host CPU/RAM/storage/filesystem, Docker limits, retained history and initial queues/cursors, external contention, warm-up/steady/drain intervals. Baseline/optimized trials must use equivalent inputs and isolated fresh state. Warm-up rule is fixed before the trial. Preserve warnings and any dropped/malformed/faulted observations in the result.

Sampling: start at 1–2 seconds for progress and resources where overhead measurement permits; event histograms use bounded reservoir/streaming quantiles. Validate timestamp alignment. Analyze early, middle and late segments, stage-native slopes with uncertainty/autocorrelation, age distributions, cyclic queue amplitude, CPU/RSS/disk/CH/Kafka behavior and confidence across repeated runs. If sampling overhead changes pacing/rate materially, lower frequency and retain a separate detailed profile run.

**Duration recommendation:** minimum four continuous representative hours after declared warm-up, plus finite disturbance and recovery while normal input continues. Rationale: at least 48 non-overlapping 300-second windows under 1x pacing and a multi-hour trace for gradual WAL/retention/merge/resource drift. Extend if trends have not stabilized or confidence is insufficient. This is a proposed minimum for owner approval, not an approved SLO. Capture separate Gold 60s/300s work age until at least multiple windows have completed and the queue trend is measurable.

## Independent oracles

| Layer | Independent expected source | Reconciliation |
|---|---|---|
| Source | SUMO run manifests/archived identities plus Outbox ledger; expected participating node/cycle set and payload bytes | Account for ACKed, pending, retry, duplicate, invalid cycle and explicit failed capture separately; no false one-to-one physical-row assumption. |
| Raw | Outbox payload bytes/event identity and Kafka topic/partition/offset; Raw ledger and physical evidence inspected independently | Exact payload byte/hash and delivery identity; offsets committed only after durable confirmation; quarantine explicit. |
| Bronze | Raw logical delivery source plus independently recomputed canonical semantic identity/hash rules; Bronze append-only change/invalidation journal | Every delivery categorized, duplicates/conflicts explicit, obligations/reconciled outputs and contiguous sequence coverage verified. |
| Silver | Bronze changes/invalidation and accepted source payload/archive; independent expected fact values, counts, availability states and lineage | Verify event validity history and current disposition, dimensions/facts/lineage, obligation hash/content, contiguous applied prefix and independent invalidation state. Never use current `silver_v1_event_validity` alone as full historical validity oracle. |
| Gold ACK | Independently retained Silver receipt sample/canonical response and source journal sequence/binding; Gold receipts/transitions | Exact sequence coverage/receipt continuity and hashes; distinguish interval/hash preservation from full historical payload reconstruction (Gold stores headers/metadata, not every original page). |
| Gold membership/work | Independent event/run/time oracle implementing fixed epoch-zero half-open 60/300s windows, suppression at fixed invalidation boundary, expected generation | Exact membership IDs, suppression and work fence; compare materialized current-effective canonical inputs to independently selected accepted facts; exact completed eligible set. |
| Full drain | Frozen final producer/source boundaries and stage high-waters; queue/obligation/work inventory independently queried | Require source entries accounted, all required Bronze/Silver outputs reconciled, Gold contiguous cursors at frozen supported boundary and all eligible work complete. Report terminal OPEN windows distinctly, not as incomplete eligible work. |

Gold evidence must state its limit: retained receipt headers and hashes prove intervals/identity but cannot reconstruct arbitrary historical payload if only the Silver source remains. Do not claim full historical payload verification from digest alone.

## Backlog stability, statistical method and headroom

For each stage record `(t, λᵢ, μᵢ, Bᵢ, ageᵢ, bytesᵢ)` at aligned intervals. Fit piecewise steady segments and report slope, uncertainty, sample count, autocorrelation-aware method, early/middle/late estimates and trial-to-trial variance. A bounded cyclic batch queue has bounded repeated peaks/troughs and near-zero long-run slope; an accumulating queue has positive slope and/or increasing oldest age/bytes across segments. Final zero lag alone fails.

Derive required headroom with owner-defined finite recovery demand: `μᵢ,target ≥ λᵢ,normal + Bᵢ/Tᵢ,recovery`. Confirm by genuine finite burst followed by normal arrivals. If a stage changes units through fan-out, estimate effective work demand from measured disposition/fan-out mix and independently count both units. Gold demand counts memberships and dirty-generation proofs, not just ACKed events. Repeat trials and do not accept a mean at λ as headroom.

## Before/after decision matrix

For each approved objective record baseline value, optimized value, delta and uncertainty for: correctness dispositions; source cadence/fidelity; per-stage λ/μ/slope/age/bytes; Silver sequences and facts/s; feed pages/bytes/query; Gold ACK/s; 60/300 work and members/s; source→ACK and eligible→complete latency percentiles; CPU/RSS/SQLite/WAL/disk/CH/Kafka; history-query cost; recovery; realtime metrics; fault/retry rates. Mark “not measured” instead of carrying prior proxy values. Accept only if all dimensions meet approved requirements and no cross-stage backlog/resource transfer is observed.

## Rejection and rollback

Reject any result with source mismatch, semantic/fact/lineage discrepancy, missed invalidation, cursor/offset jump, failed independent oracle, positive sustained required-stage backlog beyond threshold, incomplete eligible Gold work, unbounded resource/history growth, unobserved backlog transfer, realtime regression outside owner threshold, non-reproducible workload, or missing raw evidence. Stop changed workers cleanly, preserve all authority/source state, restore known-good image/config, verify cursor binding and reconcile before resume. No destructive reset/truncate used as rollback.

## Phase 4B gate

Phase 4B is not ready until Core correctness is hardened; upstream semantics and guarantees are unchanged; representative pipeline workload and Gold eligible-window work are sustainably stable with approved headroom; all required outage/recovery and independent end-to-end oracles pass; resource/history/realtime envelope is accepted; no critical performance blocker remains; and owner explicitly approves the evidence. This foundation acceptance does not certify future KPI/mart/Spring API/Dashboard latency.
