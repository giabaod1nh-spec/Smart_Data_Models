## Objective exit gates

1. Every CORE and RESILIENCE scenario A01–A33 is PASS with evidence, or an explicitly approved scope change records the exclusion. A34 EXTENDED may be run and reported separately; its omission does not block Phase 3. No inferred pass.
2. Full workload cardinalities match archive-derived independent oracle and exact row identities; values, availability, primary lineage, separately resolved complete lineage, hashes and validity reconcile independently.
3. Zero measured-zero corruption, zero unavailable-to-zero conversion, zero fabricated direction rows, zero unexplained Bronze events, and zero known-conflicted IDs exposed by canonical reader.
4. Clean install, populated-V2 upgrade and repeat migration preserve V2 database sentinels; worker starts only after 006/007/008 and source verification. No V2 cleanup is part of Phase 3. Gold V1/Spring/Dashboard implementation is not a Phase 3 PASS dependency.
5. Targeted resilience tests for crash/restart, partial/lost-response writes, source/mirror outage and replay isolation pass with cursor/validity invariants; no additional broad hardening cycle is required.
6. Actual runtime reaches READY and converges with bounded pending obligations; resource/backlog/latency results are measured for the supported local Windows/Docker Desktop profile.
7. Phase 4 handover names Gold V1 adapter changes, canonical reader tokens/failure behavior, invalidation-to-window feed, source cutoff limitation, nullable/availability model, primary/full lineage access and archive retention obligations.
